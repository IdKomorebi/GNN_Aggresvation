# DNN_Aggresvation74 日志

## Modify by Claude: 2026-07-22

## 1. 子项目定位

**回答一个能一锤定音的问题：「GNN 不如 MLP」是结构性结论，还是实现缺陷？**

项目跑了四次"GNN 不如 MLP"的负结论（63 架构 / 66 hypernet / 69 保真度 / 73 失活消融），
据此把 GNN 从主线摘掉了。但通读 42–55 号后发现：**这四次结论用的 `GNNOracle`，
和项目自己在 42–55 号调出来的最优图模型几乎没有任何关系。**

| 维度 | 42–55 号调出的最优 | 63 号 `GNNOracle`（沿用至今） | 已实测代价 |
|---|---|---|---|
| G→C 聚合 | `gcn_dynamic`：先验边 × **逐样本 sigmoid 门控**，无 q·k | q·k + **单一全局** `prior_scale`×log先验 | 这正好等于 `gat_static`。51 号 0.8523 vs `gcn_dynamic` 0.8746，且 51 §4.4 明说 `gat_static` 是"唯一稳健最差"的两个之一 |
| 相关性融合 | 可学习 `beta_general`（softmax over 5 指标，温度 2.0） | 5 指标算术平均，`register_buffer` 不可学 | 45 号 `uniform_alpha` −0.0125 |
| 输入编码 | `mlp`（2 层 MLP/节点） | `Linear(2,H)+ReLU`（= `linear` 中档） | 52 号：对 GAT 系 +0.002~+0.022 |
| 注意力温度 | 0.25（越 sharp 越好） | 隐含 1.0 | 42 号 congestion_da +0.109 |
| 层数 | 4 | 3 | 43 号 layers4 +0.007、layers2 −0.028 |
| 训练 | epochs 500 / patience 150 | 400 / 60 | 42 号充分训练 +0.035 |
| G→C 位置 | **每层**都做，conf 隐状态逐层精化 | 只在**最后**做一次 | 未测 |

**两处已核实的硬证据：**

1. `diff DNN_Aggresvation69/base.yaml DNN_Aggresvation52/configs/base.yaml` **返回 0**
   —— 数据、字段集、图参数完全一致，两边可比。
2. `DNN_Aggresvation63/scripts/train_oracle.py:73` **只读了 `cfg["graph"]["top_k"]` 和
   `["threshold"]`**。整个 `model:` 段（`num_layers: 4` / `edge_alpha_temperature: 2.0` /
   `attention_temperature: 0.25` / `hidden_dim: 64`）和 `training:` 段
   （`epochs: 500` / `patience: 150`）**对 oracle 完全没生效**。

**数值旁证**：73 号 `none` 变体（满输入训练，等价攻击者设定）满输入 R² GNN 0.821 / MLP 0.875；
同一份 base.yaml 下 52 号 `gcn_dynamic` 拿到 0.8746、`gcn_noprior` 0.8737。
oracle 侧的 GNN **光架构就丢了约 0.05 R²**，量级与"`gat_static` vs `gcn_dynamic`"的已测差距一致。

另：`GNNOracle`（hidden 128 × 3 层）参数量约 250k，**比 `MLPOracle` 的约 157k 还多**
—— 不是容量问题，是架构问题。

## 3. 预注册判据（**跑之前写死，跑完不许改**）

主指标：K=0 时对 394 个分层子集重训真值的 **MAE** 与 **Spearman**（逐 conf 口径）。

参照（73 号实测）：MLP-oracle **0.0597 / 0.9698**；63 号 GNN-oracle **0.0963 / 0.9197**。

MLP 对照直接读 `DNN_Aggresvation73/outputs/est_mlp_ours_seed0.csv`，**不重跑**。

**无论正负都有信息量**，是"彻底放弃"这个决定最重要的一个数。

**三点读数：**

1. **六种聚合方式的全部跨度只有 0.008，而到 MLP 的 gap 是 0.037。**
   本子项目的出发假设——"四次负结论被最差架构 `gat_static` 污染了"——**在聚合方式这一层不成立**。
   51/52 号在**攻击者侧**测到的 0.022 量级架构差异，到了 **oracle 侧**缩到了噪声量级（σ≈0.006）。
   这本身是一个有价值的发现：**掩码摊销任务对图聚合方式的敏感度，远低于固定字段集的推断任务。**
2. **但 42–55 号的核心机制确实复现了**，只是幅度小得多：同族内 `dynamic > static`
   （gat 0.0907 vs 0.0950；gcn_dynamic 0.0938 vs A0 的 0.0963），`noprior` 最差（0.0986）。
   即 51 §4.3 的"先验有用、且必须动态混合"在掩码场景下依然成立。
3. **准确率与保真度脱钩**：`A1_gcn_dynamic` 满输入 R² 最高（0.7766）却不是 MAE 最优；
   `A3_gat_dynamic` 满输入 R² 最低（0.7515）反而 MAE/Spearman 最优。
   **"把预测做准"和"把任意子集的泄露估准"不是同一件事**——这条对整个 oracle 方法论都有意义。

**A\* = `A3_gat_dynamic`**（按预注册主指标 K=0 MAE）。它含 gat 模式，故 Round B 多一个
`B0_temp`（注意力温度 0.25）。因 A3 与 A1 差 0.0031 < 2σ、统计上打平，
额外加跑一组建在 `A1_gcn_dynamic` 上的 `B6_all`（记作 `B6_all@A1`）作对照，不只押一个。

2. **MLP 基线经受住了检验。** 本 harness 下 3 seed = **0.0595 ± 0.0018**，

3. **`D_bypass` 是最有力的一击**：给 MLP 加一条图分支（292k 参数、500 轮训练

   在更多参数 + 更多训练的条件下，**图分支不是"没帮上忙"，而是净损失**。
4. **增益不叠加，甚至互相抵消**：`B6_all`（全叠，0.0884）比 `B2_enc` 单独（0.0854）**更差**。
   42–55 号在攻击者侧能叠出 +0.03~+0.11 的手段，到 oracle 侧不仅缩水还互相干扰。
5. **`B5_sum` 是全场最差（0.1018，−15%），比 63 号原版还差。** 这是本子项目
   **唯一一个不在 42–55 号已测范围内的新想法**（sum 聚合修复"和"型 conf 的偏置错配），
   实测方向是反的。诊断：它的 Spearman 反而不错（0.9288），坏的是**绝对标定**
   —— `count/nG` 缩放把小集合的消息压得过小。**排序没坏、幅度坏了。**

### 6.3 机制：图 oracle 输在哪个规模带

K=0 MAE 分尺寸带（图 `figures/mechanism_final_zh.png`）：

| 规模带 | MLP | B6_all@A1 | 63号GNN | 图候选缩差 |
|---|---:|---:|---:|---:|
| 1-2 | 0.0440 | 0.0642 | 0.0706 | 24% |
| 3-4 | 0.0859 | 0.1230 | 0.1362 | 26% |
| 5-8 | 0.1071 | 0.1414 | 0.1663 | 42% |
| **9-16** | **0.1234** | **0.1847** | 0.1997 | **20%** |
| 17-32 | 0.0786 | 0.0953 | 0.1370 | 71% |
| 33-44 | 0.0405 | 0.0485 | 0.1076 | **88%** |

**图架构的改进几乎全部发生在大集合端**（17–32 缩差 71%、33–44 缩差 88%，
基本追平 MLP），而**在最难的 9–16 带只缩了 20%**（0.185 vs MLP 0.123）。
机制解释：可见邻居越多，消息传递越接近满图训练分布；中等集合恰是
"邻居少到聚合失真、又多到组合爆炸"的区间，图先验在这里帮不上忙。
这与 73 号"无失活模型在 5–16 带崩得最惨"是同一个规模区间——
**中等集合是摊销 oracle 的公共难点，换图架构解决不了。**

## 7. 最终结论

**「GNN 不如 MLP」是结构性结论，不是实现缺陷。** 证据链：

1. **不是实现问题**：V1 闸门证明新代码忠实复现 63 号（K=0 MAE 差 0.0000）；
2. **不是聚合方式问题**：六种聚合全部跨度仅 0.008，而 gap 是 0.037（Round A）；
3. **不是超参问题**：42–55 号在攻击者侧验证过的全部增益（可学习 alpha / mlp 编码 /
   4 层 / 充分训练 / 注意力温度 0.25 / 逐层 G→C）逐项 + 全叠都试过，最好 31%（Round B）；
4. **不是容量问题**：`B6_all@A1` 用 167k 参数（MLP 157k）拿到 0.0851；
   而 63 号原版用 250k 参数拿到 0.0963 —— 参数更多反而更差；
5. **图分支本身是负贡献**：`D_bypass` 证明给 MLP 加图分支会让它显著变差（+5.1σ）。

**可直接进论文的表述：**

> 我们用本项目在 42–55 号中系统调优得到的最优图架构与超参（动态先验门控、
> 可学习相关性融合、MLP 节点编码、4 层传播、注意力温度 0.25、逐层读出、充分训练），
> 在同一协议下重建了图 oracle。最优图变体的摊销 MAE 为 0.0851 ± 0.0028，
> 显著劣于同预算 MLP-oracle 的 0.0595 ± 0.0018（+13.4σ），
> 且给 MLP 附加图分支反而使其显著恶化（0.0595 → 0.0653，+5.1σ）。
> 结合 hypernet（66）、元学习（65）、分带专家（68）三个独立负结果，
> **摊销集合敏感度 oracle 上结构先验的无效性不是实现缺陷，而是任务性质。**

**两个附带的正面发现（不因主结论为负而失效）：**

- **42–55 号的核心机制在掩码场景下确实复现**，只是幅度小一个量级：
  同族内 `dynamic > static`（gat 0.0907 vs 0.0950），`noprior` 最差（0.0986）。
  即 51 §4.3 的"先验有用、且必须动态混合"依然成立。
- **准确率与保真度脱钩**：`A1_gcn_dynamic` 满输入 R² 最高却非 MAE 最优；
  `A3_gat_dynamic` 满输入 R² 最低反而保真度最优。**"把预测做准"与"把任意子集的
  泄露估准"不是同一件事** —— 这对整个 oracle 方法论有意义，值得单独写一句。

**不推荐做 Round C**（换建图语义：可推断度矩阵 / 协同图 / 偏相关）。
理由：Round A 已证明**图的用法**（聚合方式）在 oracle 侧影响仅 0.008；
若换**图的内容**要闭合 0.026 的差距，需要比聚合方式大三倍以上的效应，
而 `D_bypass` 已经表明图分支整体是负贡献。若仍要做，应只做最便宜的
协同图（946 对真值现成，需交叉拟合防泄露）作为一次性收尾。
