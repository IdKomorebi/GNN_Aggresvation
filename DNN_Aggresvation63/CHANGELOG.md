# DNN_Aggresvation63 日志

## Modify by Claude: 2026-07-14

## 1. 子项目定位（主线 Phase 1：摊销泄露 oracle 保真度对决）

主线 = 集合敏感度 v_c(S)（可见字段集合 S 对机密 c 的可推断性）。核心方法是训练一个
**子集条件 oracle**：随机子集失活训练，一次训练摊销 2^44 个子集的攻击者最优响应，
查询 v̂(S) = 把测试集按 S 掩码前向、实测 12-conf 平均 R²（O(1) 一次前向）。

本子项目回答决策门：**图先验（GNN-oracle）是否让摊销在指数子集空间上比 MLP-oracle
更保真**。这直接决定"why GNN"能否落在 oracle 上。

## 2. 方法

- 两个 oracle 同一掩码分布、同一预算（`src/oracle.py`）：
  - MLP-oracle：输入 [x⊙m, m]，hidden 256×3，无图先验（强 baseline）；
  - GNN-oracle：相关图先验 + **可见性感知注意力**——被遮蔽字段既置 0 又从聚合 softmax
    中剔除（只在可见邻居上重归一化），是"沿相关边替补被遮蔽字段"的结构化实现。
    hidden 128×3。
- 掩码分布：逐样本先抽保留数 k~U{1..44} 再均匀抽 k 个字段（覆盖各尺寸带均衡）。
- 真值：60 号 50 无偏随机子集（v_best=best-of-struct 重训，主基准）+ 59 号 55 个
  top-k 结构化子集（best-of-struct）。共 105 点。各 arch 3 种子平均。
- 低数据变体：训练集截 10%/20%/50% 各训一对。

## 3. 结果（诚实的负结果：GNN-oracle 不赢）

**满数据 105 真值点：**

| oracle | MAE | bias | Spearman |
|---|---:|---:|---:|
| MLP | **0.0796** | −0.0796 | 0.9763 |
| GNN | 0.1253 | −0.1253 | 0.9779 |

**按尺寸带（GNN 假设应在 5–16 更优）：**

| 尺寸带 | MLP MAE | GNN MAE | ΔMAE | MLP rho | GNN rho | Δrho |
|---|---:|---:|---:|---:|---:|---:|
| 1–4 | 0.056 | 0.090 | +0.034 | 0.990 | 0.949 | −0.042 |
| 5–8 | 0.122 | 0.151 | +0.029 | 0.969 | 0.975 | +0.006 |
| 9–16 | 0.116 | 0.161 | +0.045 | 0.918 | 0.933 | +0.015 |
| 17–32 | 0.070 | 0.129 | +0.059 | 0.919 | 0.907 | −0.012 |
| 33–44 | 0.035 | 0.110 | +0.075 | 0.146 | 0.404 | +0.258* |

（*33–44 带真值都挤在高位、排序近噪声，rho 不可靠。）

**低数据（对 60 无偏 50 点，真值=满数据重训）：**

| frac | MLP MAE / rho | GNN MAE / rho |
|---|---|---|
| 0.1 | 0.243 / 0.976 | 0.293 / 0.950 |
| 0.2 | 0.161 / 0.980 | 0.205 / 0.972 |
| 0.5 | 0.124 / 0.984 | 0.200 / 0.963 |

三个结论：

1. **摊销泄露 oracle 这个方法本身成立且很强**：两个 oracle 对 105 个重训真值的
   Spearman 都 ≈0.98，一个模型（分钟级训练）复现了上百次逐子集重训（每次 6–7min）的
   泄露排序，查询 O(1)。**这是与架构无关的方法级正面结果。**
2. **但 GNN-oracle 不赢**：MAE 在每个尺寸带、每个数据量都劣于 MLP（系统性更低估，
   因其注意力瓶颈使满输入峰值只有 0.76 vs MLP 0.84 vs 真值 0.87）；Spearman 总体持平，
   5–16 中等带那点 +0.006/+0.015 的微弱优势远在噪声内，不构成决定性胜利。计划里
   "GNN 在中等子集/低数据更保真"的假设**未被证实**。
3. **深层教训**：在"摊销"框架下，GNN 与 MLP 在排序保真度上再次"没区别"——这正是项目
   最初痛点 1（满输入 MLP≈GNN）在集合函数层面的重演。GNN 的结构化偏置没有转化为
   摊销保真优势（bias 几乎等于 MAE，说明两者去偏后散点都很小、形状都拟合得好）。

## 4. 决策门结论与下一步

**决策门：oracle 用 MLP**（更保真、更好标定、更快）。Phase 2/3（协同图、最小防护集）
在 MLP-oracle 上推进不受影响——它们依赖 v̂ 的排序与相对差，而 MLP oracle 排序 rho 0.98。

**"why GNN" 不在 oracle 上**。GNN 若要"发光"，证据只剩两处，且都不是 oracle：
- **攻击者侧**（60 号）：逐子集重训时 GNN 攻击者在 5–16 中等子集显著赢 MLP 攻击者
  （真值 v(S) 本身在 GNN 攻击者下更高）——这是"GNN 更能从字段冗余里榨取泄露"，
  是比 oracle 机制更有意思的隐私发现，但它是关于真值的、不是关于摊销的；
- **迁移侧**（Phase 4）：去身份化节点特征 + 跨系统，MLP 结构上无法参赛。

需要用户决策：是接受"oracle=MLP、GNN 退居攻击者侧+迁移"的诚实定位继续，
还是先探一次多头注意力能否救回 GNN-oracle（我的判断：多头大概率只能追平不能超越，
即落回"没区别"，不改变本结论）。
