## 第 1 章 术语表

### 1.1 问题设定

| 符号 / 名词 | 含义 |
|---|---|
| **general 字段** | 数据持有方打算共享的 44 个字段（发电量、燃料占比、备用容量、价格等）。攻击者能读到的就是这些。 |
| **confidential 字段（conf）** | 12 个不希望被推断出来的字段：`total_gen`、`metered_load_mw`、`net_actual_interchange_mw`、`congestion_price_da/rt`、`da_as_total_mw_*` 等。 |
| **S** | 攻击者拿到的 general 字段子集。总共有 2⁴⁴ ≈ 1.76×10¹³ 种可能。 |
| **v_c(S)** | **集合敏感度**。攻击者只拿到 S 时，对 confidential 字段 c 的最佳推断精度，用测试集 R² 度量。这是全项目的核心量。 |
| **sup 语义** | v_c(S) 定义为"攻击者的最优响应"，即在所有可能的攻击模型里取上确界（supremum）。实践中近似为"在 S 上从头重训一个 DNN/GCN 攻击者，取测试集 R²"。这与"某个固定模型在 S 上的表现"不同，后者会低估。 |
| **重训真值 v_retrain(S)** | 对给定 S 从头训练攻击者得到的 R²。慢（6–7 分钟/个）但忠实，是唯一的合法定论口径。 |
| **置零口径（zero-mask）** | 早期做法：训一个满输入模型，查询 v(S) 时把 S 之外的字段置 0 再前向。**已被证明系统性低估**（56/58/73 号），因为模型从未在"字段缺失"的分布上训练过。 |
| **噪声底（σ）** | 同一个 S、同一份数据切分，只换训练种子，v_retrain 的波动。60 号测得：DNN 攻击者 σ≈0.0015，GCN 攻击者 σ≈0.0039。**任何"A 比 B 好 Δ"的结论，Δ 必须显著大于 σ 才算数。** 判读标尺：12-conf 平均口径 >0.01（DNN）/>0.02（GCN）；逐 conf 口径 >0.05。 |

### 1.2 oracle 与微调

| 符号 / 名词 | 含义 |
|---|---|
| **oracle（摊销泄露 oracle）** | 一个模型回答**任意** S 的查询。训练时每个样本随机遮蔽一部分 general 字段（"随机子集失活"），输入 `[x⊙m, m]`（值乘可见掩码，再拼上掩码本身），输出 12 个 conf 的预测。查询 v̂(S) 时把测试集按 S 掩码前向、实测 R²。 |
| **摊销（amortization）** | 一次训练换来对指数多个子集的 O(1) 查询。代价是精度：单个模型逼近的是"在所有 S 上平均最优"，而不是每个 S 各自的最优。 |
| **K** | 查询时的**微调步数**。K=0 表示直接用 oracle 前向；K=200 表示从 oracle 权重出发、在固定掩码 m_S 下做 200 步梯度更新再测。K 越大越接近重训真值，也越贵。 |
| **暖启动（warm start）** | 微调从 oracle 权重开始，而不是随机初始化（后者叫 cold start，等价于重训）。64 号实测暖启动同精度省 10–15× 步数。 |
| **两段式采样（本文的失活方案）** | 训练掩码的采样方式：先抽保留字段数 `k ~ U{1,…,44}`，再从 44 个里均匀抽 k 个。对照 `Bernoulli(0.5)`（每个字段独立以 0.5 保留，尺寸会集中在 22 附近，两端训练不足）。73 号证明两段式明显更好。 |
| **bias（系统性偏差）** | v̂ − v_retrain 的均值。全项目一致为**负**，即 oracle 系统性低估泄露。原因见"摊销"。 |
| **gap** | 特指 72 号发现的"oracle 估计与重训真值之差"在**防护后集合**上的放大：普通集合 0.04–0.14，防护后集合 0.18–0.26。 |

### 1.3 协同与低阶结构

| 符号 / 名词 | 含义 |
|---|---|
| **二阶协同 syn_c(i,j)** | `v_c({i,j}) − max(v_c({i}), v_c({j}))`。"两个字段合起来，比其中最强的那个单独用，多泄露多少"。>0 表示存在协同。 |
| **三阶不可约协同 syn3_c(i,j,k)** | `v_c({i,j,k}) − max(三个二元子集的 v_c)`。"三个一起，比任意两个一起，还多泄露多少"。这是**增量/不可约**语义：>0 说明三者缺一不可。 |
| **纯高阶（irreducible）** | 一个强三阶协同，如果它的三个二元子对的 syn2 都很弱，就叫"纯三阶"——低阶完全看不见它。68 号的例子：燃气MW + 燃气占比 + 负荷预测 → 净交换功率，syn3=0.455，而最好的二元子集只有 0.24–0.28。 |
| **m_k(S)（低阶下界代理）** | `max over T⊆S, |T|≤k 的 v(T)`。即"S 里最强的单字段/最强字段对/最强三元组能达到多少泄露"。因为 v 单调，m_k(S) ≤ v(S)，是个**下界预测器**。70 号证明 m3 校准后对宽集合排序的 Spearman = 0.969。 |
| **加性 Möbius 模型** | 把 v(S) 写成所有子集贡献之和的经典分解。70 号实测**彻底失败**（Spearman −0.216），因为 R² 有饱和上限、v 强非可加。这反过来证明了"必须用集合语义、单字段加性评分注定失效"。 |
| **等距校准（isotonic regression）** | 单调回归。用来把低阶预测的**排序**映射回**绝对值**。关键性质：单调变换不改变排序，所以校准能修绝对值、永远不能修排序。 |
| **Apriori 剪枝** | 借自频繁项集挖掘：假设"强 k 阶结构一定包含强 (k−1) 阶子结构"，于是 (k+1) 阶候选只在强 k 阶的超集里生成。70 号检验了这个假设在本数据上的成立程度。 |

### 1.4 最小防护集

| 符号 / 名词 | 含义 |
|---|---|
| **τ（阈值）** | 可接受的泄露上限，主实验取 0.5（即攻击者对任一 conf 的 R² 不得超过 0.5）。 |
| **防护集 P** | 要删除/不共享的 general 字段集合。剩下的 `44 ∖ P` 是共享集合。 |
| **危险单字段 / 危险对** | `max_c v_c({i}) > τ` / `max_c v_c({i,j}) > τ`。注意这是**泄露**超阈，不是协同超阈。 |
| **加权覆盖函数 f(P)** | `Σ_{被 P 碰到的危险项} 泄露权重`。删掉字段 i，就"中和"了所有以 i 为端点的危险单/对。 |
| **单调次模（monotone submodular）** | 集合函数的两个性质：加元素不会变差（单调）；边际收益随集合变大而递减（次模）。覆盖函数天然满足，因此预算约束下的贪心算法有 **(1−1/e) ≈ 0.632** 的近似保证。 |
| **k\*** | 覆盖所有危险项所需的最小防护集大小。τ=0.5 时 k\*=24/44。 |
| **Goodhart 效应** | "当一个指标成为优化目标，它就不再是好指标"。72 号原始结论认为纯 oracle 贪心会过拟合 oracle 的误差；补充实验证明那主要是 GNN 代理太差所致（见第 4 章）。 |

### 1.5 我在本文档中新引入的概念

| 名词 | 含义 |
|---|---|
| **共形预测（conformal prediction）** | 一种**分布无关、有限样本**的不确定性量化方法。给定一个校准集，可以给点估计配一个区间/上界，保证 `P(真值 ≤ 上界) ≥ 1−α`。不需要假设模型正确、不需要假设正态分布。本文档多处建议用它把"oracle 达标 ≠ 真达标"从缺陷变成有保证的性质。 |
| **闭合率（closure rate）** | 我在核查 D 里定义的量：`(真值 − 低阶预测) / (天花板 − 低阶预测)`。即"高阶/累积项填掉了低阶到天花板之间的百分之多少"。用来剥离 R² 上限造成的假象。 |
| **极小充分集 / 剥离法（peeling）** | 从一个高泄露的大集合出发，反复删掉"删了也不掉泄露"的字段，直到不能再删。得到的集合就是不可约的、可能是任意阶的协同结构。每找一个只要 O(\|S\|²) 次查询，不需要枚举 C(44,k)。 |
| **逐次减半（Successive Halving）** | 一种预算分配策略：先用最便宜的评估（K=0）筛掉大部分候选，剩下的用更贵的评估（K=50），再剩下的用最贵的（K=200/重训）。有 best-arm identification 的理论保证。 |

### 2.1 一句话总结项目现状

**正面结果集中在"问题形式化 + 测量方法学 + 应用"三块，且都做得很扎实。
四个"让模型更聪明"的赌注（GNN 架构 / Reptile 元学习 / FiLM hypernet / 难度分带专家）
全部为负结果，且根因一致。**

这个格局的含义：故事完整、诚实、自洽，但**方法新颖性偏薄**——现在能拿出手的
"新方法"只有"两段式失活采样"（73 号刚证实）和"暖启动省 10–15× 步"（工程贡献）。
第 5 章的所有改进建议都是瞄着这个缺口去的。

### 2.2 四个负结果的价值（不要浪费）

63（GNN 架构）/ 65（Reptile）/ 66（hypernet）/ 68 Part A（分带专家）四次失败，
共同指向一个结论：**在均匀掩码分布下，K=0 摊销的残差是"映射的内在难度"，
不是容量、初始化或条件化机制能绕过的。** 这本身是有价值的边界结果，
应该写成论文的一个消融/边界章节，而不是藏起来。

**但 68 号的归因需要收窄。** 68 号从"equal 配置给 5× 总容量仍不赢 uniform"
推出"不是容量稀释、是内在天花板"。这个推理有个缺口：分带专家只改了"**谁来算**"，
没改"**训练预算在查询分布上怎么分配**"——每个专家在自己带内仍然是均匀采样。
而 73 号恰好证明了采样分布是最灵敏的旋钮（Bernoulli → 两段式，K=0 MAE 降 43%）。
所以正确的结论应该是"**在均匀掩码分布下**容量不是瓶颈"，这给第 5 章 Q2 的
D1/D2 留出了空间。

### 3.1 核查 A：K=0 的 oracle 对最强二阶协同**结构性失明**

**问题**：69 号报告"K=0 时 MLP oracle 对二阶协同的 Spearman = 0.671"。

E[Y\|X_S] 在所有 S 上的平均；一个 masked-input 的 ReLU MLP 在"平均"意义上
根本不会去学一个只在 2/44 个字段同时可见时才成立的除法。只有逐子集微调
才会把容量押在这个特定的函数形式上。

**两条附带的、同样有用的发现**：

1. **K=0 是零误报、低召回的筛选器**：真无协同的 10425 条里，估计 >0.1 的一条都没有
   （误报率 0.00%）。这个刻画比"Spearman 0.671"精确得多，而且直接支持
   "K=0 全扫 + 微调复核"的两级协议——K=0 可以放心用来剪枝，但**不能**用来定 top。
2. **失明在 K=10 到 K=50 之间被治好**：top10 的估计排名中位数从 1276 跳到 6。
   这给"扫描协议该用多大的 K"一个精确的答案：**K=50 是分水岭，K=10 不够**。
   （对照：72 号的扫描内循环用的正是 K=50，事后看是对的。）

### 3.3 核查 C：70 号 Apriori 的 "85%" 有选择偏差，无偏重算是 94.7%

**先澄清两个数**（这两个数在项目里容易混）：

- **0.795 是 Spearman**：68 号 K=200 的 syn3 估计 vs 重训认证的 syn3，n=397 组三元组。
- **85% 是 recall（召回率），不是 Spearman**：70 号
  `calibration_and_hierarchy.py` 的口径是——在**已认证的强三阶协同**
  （`syn3_true > 0.10`）中，有多少条**含有一个强二阶子对**（`syn2 > 0.10`，同一 conf）。
  它衡量的是"用 Apriori 剪枝会漏掉多少真三阶"。

**问题**：这 85% 是在 `triple_top` 组里算的，而 `triple_top` 是 MLP 估计器
自己从 13244 个三元组里挑出的 top200 再认证的结果——只占全空间
(三元组 × conf) 条目的 **1.487%**。**用被筛选器挑过的池子去评估筛选器的漏检率，
是循环论证（selection bias）。**

修正办法现成：68 号同时认证了 **200 个随机三元组**（2400 条），那是无偏抽样。

脚本：`verify_apriori_selection_bias.py`

| 池子 | 条目数 | 强三阶 | 基率 | **recall** | Wilson 95% CI | 保留率 | 加速 |
|---|---:|---:|---:|---:|---|---:|---:|
| `triple_top`（有偏，70 号原口径） | 2364 | 314 | 13.28% | 0.850 | [0.81, 0.89] | 42.0% | 2.4× |
| **`triple_rand`（无偏）** | 2400 | 19 | **0.79%** | **0.947** | **[0.75, 0.99]** | 20.8% | **4.8×** |

**结论**：无偏口径下 Apriori 剪枝反而**更好**（recall 94.7%、加速 4.8×），
但 n=19 太小、CI 太宽。

**正确的写法**：
> "在无偏随机三元组样本上，Apriori 剪枝的 recall 点估计为 0.947（18/19，
> Wilson 95% CI [0.75, 0.99]），保留率 20.8%（加速 4.8×）。样本量偏小，
> 需扩大随机认证样本以收紧区间。"

**附带一个可写的数**：随机三元组的强三阶基率只有 **0.79%**，坐实"协同是稀疏结构"，
也解释了为什么"扫描 + 认证"协议能奏效。

**关于"三阶真实值算了吗"**：算了。`DNN_Aggresvation68/outputs/retrain/t*.json`，
397 个三元组 × 12 conf 的重训真值，就是上表的 `syn3_true`。

### 3.4 核查 D：70 号"残差到 9–16 达峰后回落"是天花板假象 —— **需要更正**

**70 号原表**（`residual_by_size.csv`）：

| 规模带 | 残差（真值 − 最强对） |
|---|---:|
| 5–8 | 0.089 |
| 9–16 | 0.167 |
| 17–32 | 0.148 |
| 33–44 | 0.126 |

据此写成："残差真实存在但**有界、且不随规模发散**，在 9–16 达峰后回落……
高阶/累积泄露是'补足项'而非主导项。"

**问题**：R² 有硬上限。集合变大时，(a) 最强字段对 m2(S) 本身已经很高
（大集合大概率含"风电 MW + 占比"这类极强对）；(b) 真值又贴着该 conf 的天花板。
两者之差被**机械地压扁**。所以"回落"可能纯粹是天花板效应。

脚本：`verify_residual_ceiling.py`。两处修正：
1. 用**每个 conf 自己的**经验天花板（\|S\|≥40 的最大重训 R²），而不是全局常数
   ——各 conf 天花板从 `congestion_price_da` 的 0.649 到 `total_gen` 的 0.994，
   跨度 0.345，用全局常数会严重失真；
2. 剔除 m2 已顶到天花板的条目（余量 ≤ 0.05，共 110/480 条，这些条目残差必然≈0，
   混在均值里正是"回落"的来源）。

**重算结果**：

| 规模带 | n | 真值 | 最强对 m2 | 天花板 | 残差 | 余量 | **闭合率** |
|---|---:|---:|---:|---:|---:|---:|---:|
| 5–8 | 110 | 0.506 | 0.410 | 0.861 | 0.096 | 0.452 | **0.250** |
| 9–16 | 105 | 0.682 | 0.492 | 0.855 | 0.190 | 0.363 | **0.559** |
| 17–32 | 84 | 0.737 | 0.526 | 0.830 | 0.211 | 0.304 | **0.726** |
| 33–44 | 71 | 0.788 | 0.575 | 0.808 | 0.214 | 0.233 | **0.913** |

残差：0.096 → 0.190 → 0.211 → 0.214，**单调上升**。
闭合率：0.250 → 0.559 → 0.726 → **0.913**，**单调上升**。

**结论（更正建议）**：

> 高阶/累积泄露**不会**随集合变大而衰减，反而**持续增强**——大集合里
> "低阶预测到天花板"之间的缺口有**九成**由高阶/累积项填补。
> 绝对残差在 9–16 之后的"回落"是 R² 上限把差值压扁造成的假象。

**这同时回答了用户对那句话的困惑**：
- **不是**"遍历空间变小"；
- **不是**"字段数多到一定程度就不存在没找到的协同"；
- 也**不能**推出"纯二阶最多、纯三阶次多、到纯九阶就没有了"。

**"纯 n 阶协同最多到几阶"这个问题，现有数据回答不了**（只做到三阶）。
要回答它，唯一便宜的路是第 5 章 Q6 的 **H3 剥离法**：统计极小充分集的 size 分布。

**重要**：70 号的**核心主张不受影响**——"泄露的排序是低阶可决定的"
（m3 校准后 Spearman 0.969）依然成立。要改的只是"残差有界不发散、
高阶是补足项"这一句，以及由它推出的"高阶不改变排序"的强度。

### 4.1 72 号的"Goodhart"结论已被自己的补充实验推翻

**72 号 CHANGELOG 第 3 节**写道：

> "纯 oracle 贪心过拟合代理（Goodhart 效应实证）……对一个有噪声且系统性低估的
> 代理指标做短视贪心，优化的是代理的误差而非真实目标。低阶真值骨架反而稳健。
> 这是'为什么不能只用 oracle'的最有力实证。"

**但 `DNN_Aggresvation72-71Supplement` 已经推翻了它**。补充实验用更准的
MLP-oracle 重跑，并修正了"重训证书用测试集 early-stop"的泄漏，结果（独立 test 重训，
三种子）：

| k | 低阶/混合 + MLP | 纯 MLP-oracle | 原 GNN 混合 | 原 GNN 直接 |
|---:|---:|---:|---:|---:|
| 24 | 0.783 | **0.777** | — | 0.844 |
| 27 | 0.652 | **0.603** | 0.648 | 0.814 |
| 30 | **0.457** ✅ | 0.578 | — | 0.813 |

补充实验的原话："纯 MLP-oracle 贪心在 k=24 并不比低阶骨架差，k=27 反而更好；
因此不能再说'纯 oracle 贪心必然过拟合代理并劣于低阶真值'。原 Goodhart 现象
主要是**较差 GNN 代理 + 反复优化其误差**的组合结果。"

**建议**：所有对外表述以补充实验为准。Goodhart 应弱化为
"**当代理质量差时**，对其做短视贪心会放大其误差"——这仍然是有价值的观察
（GNN 直接搜索 k=30 时 oracle 估 0.549、重训 0.813，低估 0.264），
但不能写成 oracle 贪心的固有缺陷。

### 4.2 "协同图"实际是"危险对图"

71/72 的形式化里，边的定义是 `max_c v_c({i,j}) > τ`，即**字段对的泄露超阈**。
但文档里一律称之为"协同图"。两者不同：

- 一对可能因为**其中一个字段单独就泄露**而被标为危险（完全没有协同）；
- 一对可能有很强的协同，但两个字段单独都弱、合起来仍未超过 τ（不会被标危险）。

**建议二选一**：
1. 保守做法：改叫"危险对图（hazardous-pair graph）"，术语统一即可；
2. 更好的做法：把边权改成 `max_c syn_c(i,j)`（真协同），节点权用单字段泄露
   `max_c v_c({i})`。这更贴合"最小防护集"的语义，也更能体现
   "单字段方法有盲区"这个卖点——毕竟 72 号 Part D 已经发现
   风电 MW（单字段泄露仅 0.068）因协同而必须进防护核心，那正是协同图该做的事。

## 第 5 章 九个问题的逐条分析与改进方案

### Q1. 图结构：现在为什么输、本质优势在哪、建图怎么改

#### Q1.1 先摆正一个事实：目前**没有**"GNN 在大集合有优势"的证据

63 号的分带表里，GNN-oracle 在**每一个**尺寸带的 MAE 都更差，而且**越大越差**：

| 尺寸带 | MLP MAE | GNN MAE | 差 |
|---|---:|---:|---:|
| 1–4 | 0.056 | 0.090 | +0.034 |
| 5–8 | 0.122 | 0.151 | +0.029 |
| 9–16 | 0.116 | 0.161 | +0.045 |
| 17–32 | 0.070 | 0.129 | +0.059 |
| **33–44** | 0.035 | 0.110 | **+0.075** |

真正有 GNN 优势的证据只有两处：

1. **攻击者侧、中等集合**（60 号，50 个无偏随机子集）：GCN − DNN 在
   5–8 带 **+0.0235**、9–16 带 **+0.0130**，超过 σ=0.0039 的标尺，可信；
2. **迁移侧**：尚未做（Phase 4）。

而 69 号对 9 个字段对 + 9 个三元组的分层审计里，GCN 反而低 0.038 / 0.029。

**正确表述**：GCN 在**中等规模子集的专用攻击者**上把攻击上限做得更强，
但作为**通用 oracle** 更差。**不要写成"大集合有优势"**——现有数据是反的。

#### Q1.2 GNN 输在哪：我读代码找到了三个具体的架构病因

看 `DNN_Aggresvation69/src/oracle.py:94-109`，`GNNOracle` 的 confidential 读出是：

```python
attn = torch.softmax(score, dim=-1)   # 在可见 general 上归一化
attn = attn / attn.sum(-1, keepdim=True).clamp(min=1e-12)
ctx  = torch.bmm(attn, v)             # (B, nC, H) —— 一个凸组合
outs = [self.heads[c](ctx[:, c, :]) for c in range(self.nC)]
```

**病因 1：softmax 归一化 = 加权平均，丢掉了"有多少个可见字段"和"总量"信息。**
而本数据集里最重要的两个 conf——`total_gen` 和 `metered_load_mw`——本质上就是
可见字段的**和**。用 mean-aggregation 去逼近一个 sum，是教科书级的归纳偏置错配
（GIN 论文的核心论点）。相比之下，MLP 拿到 `[x⊙m, m]` 天然能做加法。

**病因 2：单头 + 凸组合 = 秩瓶颈。** 12 个 conf 各自只能看到一个 H 维的加权平均
向量，无法表达 `MW / pct` 这种乘除交互。63 号 CHANGELOG 记的
"注意力瓶颈使满输入峰值只有 0.76 vs MLP 0.84 vs 真值 0.87"就是这个。

**病因 3：`A_gg` 是固定 buffer，完全不可学习。**
`self.register_buffer("A_gg", ...)`——图是死的。而攻击者侧的 `model.py` 里
明明有可学习的相关系数权重 α 机制（用户的"改进方向.md"里 GNN1–GNN13 全在调这个），
oracle 侧却一点没用上。

#### Q1.3 架构改法（按性价比排序）

| # | 改动 | 说明 | 预期 | 成本 |
|---|---|---|---|---|
| **G1** | **sum-aggregation + 可见数** | `ctx = Σ_j a_j·v_j`（不做 softmax 归一化），并把 `Σ_j m_j`（可见字段个数）拼进 head 输入 | 直接修复"总量类 conf"的偏置错配。**我判断这是单项最大收益** | 改 ~5 行 |
| **G2** | **多头注意力 + concat** | 4–8 头，拼接而非平均 | 解秩瓶颈。注意 63 号 CHANGELOG 已预判"多头大概率只能追平"——那是在没修 G1 的前提下说的 | 改 ~20 行 |
| **G3** | **`A_gg` 改成 `nn.Parameter`** | 用相关先验做**初始化**而非硬约束，边权过 softplus 保非负 | 让图能被数据修正；最差退化到学出全连接≈MLP，不会更糟 | 改 ~10 行 |
| **G4** | **乘性交互项** | 沿边聚合 `h_i ⊙ h_j`（bilinear） | 直接瞄准 MW × pct 这类协同 | 中 |

> **重要**：G1–G3 应该被当作"**把对照做公平**"的必要工作，而不是"再赌一次 GNN"。
> 现在的结论"GNN 不如 MLP"存在被审稿人指为**实现缺陷**的风险
> （softmax-mean 聚合去预测 sum 是明显的设计失误）。修完再报同样的负结果，
> 结论才站得住。

#### Q1.4 建图怎么改 —— 这是用户问的重点，我有四个方案

**当前建图**（`base.yaml` + `model.py:526 build_edge_mask`）：
5 种相关系数（pearson / spearman / kendall / nmi / dcor）取**算术平均** →
`top_k=8` 或 `≥ threshold 0.15` → 对称化 → 清空 conf-conf 块（bipartite）。

**(a) 根本问题：相关系数对本任务的核心目标——协同——结构性失明**

`gen_fuel_wind_mw` 与 `total_gen` 的边际相关只有 0.06，`gen_fuel_wind_pct` 是 0.16，
但两者合起来 R² = 0.93。**任何基于成对边际相关的建图，都不可能把这条最重要的

### Q2. 随机失活方法还能怎么改进

#### Q2.1 先诊断"分规模为什么失败"

68 号 Part A 的难度分带专家失败了，失败得很有信息量：**equal 配置给每个专家满 256
隐藏（5× 总容量）仍不赢 uniform**，这排除了"容量被 2⁴⁴ 个任务稀释"的假设。

**但我认为 68 号的归因（"内在难度天花板"）下得太早**，理由见 §2.2：
分带只改了"谁来算"，没改"训练预算在**查询分布**上的分配"。

而 73 号恰恰给了反证：**只改采样分布（Bernoulli → 两段式），K=0 MAE 就从 0.105
降到 0.060（−43%）**。采样分布是这个系统里**已被证明最灵敏的旋钮**。
所以"随机失活已到天花板"的结论我不接受。

#### Q2.2 四个改进方向

**D1. 查询分布匹配采样（最推荐，最便宜）**

现在训练是"尺寸均匀 `k ~ U{1,…,44}`"，但**实际查询分布完全不是均匀的**：

| 用途 | 实际查询的 \|S\| |
|---|---|
| 二阶协同全扫 | 1, 2 |
| 三阶协同全扫（13244 个） | 3 |
| 防护集验证（共享补集） | 14 ~ 44 |
| **几乎不查** | **5 ~ 13** |

尺寸均匀采样把 1/44 的训练预算花在 \|S\|=25 上，而那里几乎没有查询；
`|S|=3` 承载了扫描协议 90% 以上的查询量，也只拿 1/44。

> **改法**：按实际 workload 加权的重要性采样。例如
> `50% 预算给 |S|≤3 + 30% 给防护集补集尺寸区间 + 20% 兜底均匀`。
>
> 这也顺便解释了分带专家为什么无效：它**均分**了带，等于强化了错配。

**D2. 结构化 / 对抗性掩码（最推荐，直接打 72 号的痛点）**

均匀随机 k-子集**几乎永远不会**同时包含 `wind_mw` 和 `wind_pct`：
概率 = C(42, k−2)/C(44, k) ≈ k²/1892，k=3 时只有 **0.5%**。
而这正是最强协同所在——**训练时几乎没见过，K=0 当然失明**（呼应核查 A）。

同理，72 号发现 oracle 在"被贪心精心削弱的集合"上 gap 放大到 0.18–0.26，
因为那些集合是分布外的。

> **改法**：训练掩码改成混合分布
> ```
> 60% 尺寸均匀（现状，兜底）
> 20% 相关块/协同对成组保留或成组遮蔽（让模型见到 MW+pct 同时可见的情形）
> 20% 从上一轮贪心防护集的补集里采样（self-play / hard negative mining）
> ```
> 第三项是**闭环**的：跑一轮防护贪心 → 把产生的补集加入掩码池 → 重训 oracle →
> 再跑贪心，迭代 2–3 轮。
>
> 这**直接**修 72 号的"对抗性削弱集合上低估放大"，是整条防护管线最大的单点缺陷。
> 而且"对抗性掩码课程"本身有方法新颖性——现有的 FastSHAP / Knockout
> 等摊销范式全都用 i.i.d. 掩码。

**D3. 目标函数：从 mean 逼近 sup**

系统性低估（bias ≈ −MAE，63 号）的根因是：单模型逼近的是 E_S[E[Y\|X_S]]，
而真值是逐子集的 sup。两个可试的修法：

- **难例加权**：per-subset 损失按当前误差重加权（focal loss 风格），
  别让容易逼近的大集合吃掉全部预算；
- **分位数 / pinball 损失**：直接训一个 τ=0.9 分位数的预测器，得到天然保守的估计。
  这和 Q3 的共形上界是同一思路的两种实现，可以互相验证。

**D4. 换一个摊销对象（我认为这条最有方法新颖性）**

现在的 oracle 是**替身模型**：预测 Y，然后前向测 R² 得到 v̂。
所以它继承了"逼近条件期望"的全部偏差。

> **另一条路：直接训一个集合函数回归器 `g(S) → v_c(S)`**
> （DeepSets 或 Set-Transformer over 字段嵌入）。
>
> - **标签**：已攒下的 1437 条重训真值 + 990 条低阶穷举真值；
> - **输入特征**：集合的元素嵌入 + `m1(S), m2(S), m3(S)`
>   （低阶代理，70 号已证 Spearman 0.969）；
> - **关键性质**：它的训练目标**就是 sup 语义的重训真值**，
>   因此**没有系统性低估**，也不需要微调；
> - 相当于"用神经网络学 70 号那条等距校准曲线的高维版"。
>
> 这条和现有 oracle **不冲突、可以互补**：现有 oracle 负责在真值稀疏的区域外推，
> `g(S)` 负责在有真值的邻域内精修。而且 DeepSets 天然是置换不变的集合结构，
> 是 GNN/集合网络翻身的另一个机会。

### Q3. 校准还能不能改进 —— 能，而且这是当前最被低估的一环

用户说"想不到能改什么"。我认为原因是**校准的定位错了**。

#### Q3.1 现状与它的死胡同

现在的校准有两处：
- 67 号：per-(size, K) 的标量偏差，2 折交叉拟合；
- 70 号：对低阶代理做等距回归（isotonic）。

两者的目标都是"提高绝对精度"。但 72 号的命题 2(d) 已经证明：
**等距回归是单调变换，不改变排序；per-size 校准只是平移常数，也不改序。**
所以校准**注定对排序零贡献**（67 号实测 `spearman_cal ≈ spearman_raw`，
完全符合理论）。它只能做"提精度"这一件它做不好的事——K≥50 之后微调已经把偏差消掉了。

**结论：在现在的定位下，校准确实没什么可改的。用户的直觉是对的。**

#### Q3.2 但项目里有一个更严重的、校准恰好能解决的问题

> 72 号：oracle 说 0.474 达标，重训真值 0.654 不达标，gap 0.18–0.26。
> 补充实验：k=29 时 MLP-oracle 0.476，重训 0.541，**又是一次假达标**。

这是**覆盖率问题**，不是精度问题。**点估计校准无论多准，都无法给出"不会假达标"
的保证。** 正确的工具是共形预测。

#### Q3.3 C1：单边共形上界（强烈推荐）

项目已经有 **1437 + 990 条重训真值**作为校准集——这是别人没有的资产。做法：

```
在校准集上计算残差   r_i = v_retrain(S_i) − v̂_oracle(S_i)
取 (1−α) 分位数        q = Quantile_{⌈(n+1)(1−α)⌉/n}(r)
输出上界               v̂_up(S) = v̂(S) + q
```

**保证**：`P(v_retrain(S) ≤ v̂_up(S)) ≥ 1 − α`，**分布无关、有限样本**
（只需要校准集与查询点可交换，不需要模型正确、不需要正态假设）。

这一步把整条管线的性质彻底改变：

1. **"oracle 达标 ≠ 真达标"从缺陷变成被量化控制的性质**。
   报"v̂_up = 0.70 @ 95% 置信"而不是"v̂ = 0.474（但实际 0.654）"。
2. **免疫 Goodhart**。72 号发现对代理做贪心会放大代理的误差。
   **对上界做贪心是保守优化**——你优化的是"最坏情况的最坏情况"，
   不会被代理的乐观误差骗到。这直接修掉 72 号最尴尬的负结果
   （虽然补充实验已部分推翻，但"边界处假达标"仍然存在）。
3. **论文层面**：τ 达标从工程声明升级为**带覆盖保证的证书**。
   安全会议非常吃这一套。

#### Q3.4 C2：条件化校准（Mondrian / 加权共形）

72 号已经量到"防护后集合的 gap 远大于普通集合"，说明残差**不是同分布的**，
无条件共形会在最关键的区域欠覆盖。两个修法：

- **Mondrian conformal**：按 `(尺寸带, conf, 是否来自贪心搜索)` 分层，各层独立取分位数；
- **加权共形**（Tibshirani et al., NeurIPS 2019, "Conformal Prediction Under
  Covariate Shift"）：防护集补集是被贪心挑出来的，属于协变量偏移，
  用似然比对校准集重加权。

#### Q3.5 C3：逐 conf 校准（现在没做，但显然该做）

核查 D 顺带给出了各 conf 的经验天花板（`outputs/q7_conf_ceilings.csv`）：

```
congestion_price_da   0.649   ←  最低
congestion_price_rt   0.663
...
metered_load_mw       0.991
total_gen             0.994   ←  最高
```

**跨度 0.345。现在 12 个 conf 共用一条校准曲线，这肯定是欠拟合的。**
逐 conf 等距回归几乎零成本。

#### Q3.6 C4：多特征校准而非只按 size

现在只以 `size` 为条件。可用的条件特征还有：`m1/m2/m3` 低阶代理值、
可见字段在协同图上的度数、`Σm`、K、conf。

> 用一个小 GBDT 拟合残差 `r = f(v̂, size, m2, m3, conf, …)`，再对**它的残差**做共形。
> 这是标准的 **conformalized quantile regression**，能把上界收得更紧
> （q 更小 = 更少的保守浪费 = 更实用的防护预算）。

**成本估计：C1 + C3 半天，纯 CPU，不需要重训任何模型。
收益：把整条防护管线的结论从"经验"升级为"有保证"。
这是全项目性价比最高的单项改进。**

### Q4. 微调：有没有更少步数、更接近真实重训的办法

用户的方向是对的，元学习失败也不奇怪。

#### Q4.1 先确认两个已被证伪的方向，不要再走

- **65 号 Reptile**（学一个万能初始化）：四配置全败，且比 naive 暖启动更差。
  诊断"子集任务的最优解在参数空间铺得太开，不存在一个对所有子集 10 步可达的初始化"
  **我认为是正确的**。
- **66 号 FiLM hypernet**（学一个 mask → 参数的映射）：K0 = 0.0916 vs 63 号 MLP 的

#### Q4.2 但还有四条根本不同的路，都没试过

**F1. 学习曲线外推（最便宜，今天就能验证，不用 GPU）**

你要的不是微调后的**模型**，而是一个**标量 R²**。那就不必真的微调到收敛
——用前几步的曲线**外推**：

```
R²(K) ≈ R²_∞ − a·K^(−b)        （幂律）
或     ≈ R²_∞ − a·exp(−bK)     （指数）
```

用 K ∈ {0, 10, 50} 三点拟合，预测 R²_∞，与 K=500 的实测对比。

> **关键：验证这个想法完全不需要新实验。**
> - 67 号 `outputs/est/*.json`：990 个子集在 K ∈ {0,10,50,100,200,500} 的完整曲线；
> - 68 号：13244 个三元组的 K 扫描。
>
> 跑一个拟合脚本，**半小时出结论**。如果 K=50 外推能达到 K=500 的精度，
> 扫描成本直接降 10×。
>
> 这在 AutoML/NAS 里是成熟技术（learning curve extrapolation），
> 移植到集合敏感度上是干净的方法组件。

**我认为这条成功概率很高**：64 号的四臂曲线看起来非常规整（幂律状），
且 67 号 K=200 → 500 的改善已经很小（Spearman 0.928 → 0.960）。

**F2. 同伦 / 增量微调（homotopy warm-start）**

现在每个子集都从**全局 oracle** 暖启动。但扫描 13244 个三元组时，
相邻三元组高度重叠（共享 2/3 的字段）。

> **改法**：
> - 把查询序列按 **Gray code / 最小汉明距离**排序，每个子集从**上一个**
>   已微调好的解暖启动，而不是从全局 oracle；
> - 或**层级式**：三元组 (i,j,k) 从它最强二元子集 (i,j) 的微调解暖启动
>   ——**二元的解你已经全算完了**（946 对）。
>
> 这利用的是"**相邻子集的最优解也相邻**"，恰恰绕开了 65 号发现的
> "全局任务太发散"——**局部不发散**。
> 这是对 65 号负结果的**正确回应**，而不是重复它。

**F3. 闭式最后一层 + 交互特征扩展（这条最有可能直接大赢）**

64 号的 `warm_head` 臂 plateau 在 0.070，结论是"必须动表示层"。
**但我认为那个结论下错了**——问题不在"只调头"，而在于**头看到的特征空间里
没有它需要的东西**。

回到核查 A 的发现：K=0 失明的全是 `MW / pct` 这种**乘除法**。
一个在平均掩码分布上训练的 ReLU 表示，倒数第二层里根本没有编码 `x_i / x_j`。

> **改法**：把最后一层换成对
> `[h_penultimate, x⊙m, {x_i · x_j}, {x_i / (x_j + ε)}]`
> （交互项只在**可见**字段对上取）的**岭回归闭式解**：
>
> - 闭式解 = **零梯度步**，成本接近 K=0；
> - 交互项直接提供了协同所需的函数类；
> - 岭系数可用留出集选，也是闭式的（GCV）。
>
> **预期**：K=0 就能把 `wind_mw + wind_pct → total_gen` 从"排名 11303"救到 top 区。
>
> **如果这条成立，它同时解决 Q2（失活）、Q4（微调）、Q5（协同发现）三个问题**
> ——是全项目单项收益最高的实验。
>
> 实现注意：44 个字段的两两交互是 C(44,2)=946 项，加上比值是 1892 项，
> 岭回归完全吃得下（n_train ≈ 4000）。可以先只加"同族字段对"

### Q6. 高阶协同：评价怎么修，以及更快更全更准的搜法

#### Q6.1 评价问题（已在第 3.3 节回答）

摘要：
- 85% 是 **recall** 不是 Spearman；0.795 才是 Spearman；
- 85% 算在估计器选出的 1.487% 池子里，有选择偏差；
- 无偏重算 = **94.7%（18/19），Wilson 95% CI [0.75, 0.99]，加速 4.8×**；
- 三阶真值算了（397 个三元组的重训认证）。

**"假如确实存在问题，应该怎么评价"** —— 三条原则：

1. **评估池必须独立于筛选器**。用 `triple_rand` 那 2400 条无偏样本作为唯一的
   recall 评估集。当前 n=19 太少。
   > **建议：把随机认证样本从 200 个三元组扩到 2000–3000 个。**
   > 按 68 号的重训速度（~6.5 分钟/个，4 GPU 并行）约 **4–6 GPU 小时**。
   > 这是花小钱换硬结论——CI 能从 [0.75, 0.99] 收到 ±3%。
2. **报 recall 必须配保留率/加速比**。单独的 recall 没有意义
   （保留 100% 时 recall 恒为 100%）。应该画成 **recall–cost 曲线**（扫 δ 阈值）。
3. **更好的是别用启发式剪枝，用有保证的剪枝**（见 H1）。

#### Q6.2 四个搜索方案

**H1. 共形 UCB 剪枝 —— 把"85% 大概"换成"漏检率 ≤ α 有保证"**

结合 Q3：给 K=0 的 syn3 估计配一个 (1−α) 共形**上界** `syn3_up`。然后：

```
若 syn3_up(i,j,k,c) < δ  →  安全剪掉（漏检概率 ≤ α，有证书）
否则                     →  进入微调 / 重训认证
```

把 Apriori 的启发式（"含强二阶子对"，无法保证、且 15% 纯高阶漏网）
换成**可证的漏检率**。而且 K=0 全扫 13244 个三元组本来就便宜（一次前向）。

**这是我最推荐的一条**，因为它把 Q3 的共形工作直接复用了，
两处工作合成一个方法组件。

---

**H2. 逐次减半 / 最优臂识别 —— 把 K 当预算而不是常数**

现在是"所有候选一律 K=200"。但 90% 的候选在 K=0 就明显是零
（核查 A：K=0 误报率 0.00%）。改成 **Successive Halving over K**：

```
13244 个候选  @ K=0   →  保留 top 25%  (3311)
   3311 个    @ K=50  →  保留 top 25%  ( 828)
    828 个    @ K=200 →  保留 top 25%  ( 207)
    207 个    →  重训认证
```

总成本 ≈ 全体 K=200 的 **1/8 ~ 1/10**，而且这是有理论保证的
best-arm identification 框架（Hyperband / SH）。

> **关键：现有数据可以离线模拟出这个调度的 recall，不用跑新实验就能验证。**
> 68 号有 13244 个三元组在多个 K 下的估计，直接重放即可。

---

**H3. 不枚举 —— 用"剥离法"找不可约极小集（我认为最有方法新颖性）**

四阶以上枚举必然爆炸：C(44,4) = 135751，C(44,5) = 1086008。
但你其实不需要枚举，因为你要找的是**极小充分集**
（minimal sufficient set，对应逻辑里的 prime implicant）：

```
对每个 conf c：
    从一个已知高泄露的集合 S₀ 出发（全集，或贪心 top-k）
    重复：
        找一个 f ∈ S，使得 v_c(S ∖ {f}) 仍然 > δ   →   删掉 f
    直到不能再删                                   →   得到极小充分集 M
    随机化删除顺序 + 多次重启                       →   枚举出多个不同的 M
```

**每找一个 M 只需 O(\|S\|²) 次 oracle 查询（几百次，秒级），
而不是 C(44,k) 次。**

它的四个好处：

1. **自动发现阶数**，不用预设 k——\|M\| 可能是 3、5、9，由数据决定；
2. 返回的**正是**不可约高阶协同（按定义，删任一元素就失效）；
3. **直接给防护集用**：要阻断 c，防护集必须**命中每一个** M
   ——这就是超图击中集（见 Q8.2），两条线合并；
4. **直接回答用户 Q7 的疑问**："纯 n 阶协同到几阶为止"
   = 统计所有 M 的 size 分布。**是测出来的，不是猜的。**

**这条我强烈推荐。它把"高阶协同发现"从组合爆炸问题变成线性问题，
足以撑起一个方法章节。**

---

**H4. 定义上的补强（可选）**

现在 `syn3 = v(ijk) − max(pairs)` 是"增量/不可约"语义，
**对安全场景是对的**（它回答"是否缺一不可"）。
但审稿人可能问公理化基础。

> 可以**附带**报一个 **三阶 Shapley 交互指数**做交叉验证。
> 注意**不要替换**主定义——max 语义对"最小防护集"更有用（对应击中集），
> Shapley 语义对"归因"更有用（对应贡献分配），两者互补，不是替代关系。
>
> 另注意：70 号试过的"加性 Möbius 二阶模型"（Spearman −0.216 崩掉）
> 与 Shapley 交互指数**不是一回事**——前者是用低阶项**重建** v，
> 后者只是**度量**交互。前者崩掉不代表后者没用。

### Q7. "但高阶残差在集合变大后没有一直爆炸，而是到 9～16 字段左右达到较高水平后回落"

### Q8. 最小防护集

#### Q8.1 四个方案到底是什么（用户说没看懂——因为它们分布在 71 和 72 两个号里，而且是两个不同层次的对比）

**71 号 Part A/B 比的是「选哪些字段删」的四种排序策略**
（全部只用现成低阶真值，不查 oracle）：

| 策略 | 怎么选 | 直觉 |
|---|---|---|
| **贪心（本文）** | 每步选**边际覆盖收益**最大的字段。覆盖收益 `f(P) = Σ_{被 P 碰到的危险单/对} 泄露权重`，每步取 `argmax_f [f(P∪{f}) − f(P)]` | **协同感知**：删一个字段能同时中和它参与的所有危险对；而且**每步都更新**，不会重复覆盖 |
| **加权度基线** | 一次性按 `deg(f) = Σ 含 f 的危险项权重` 排序，取前 k | 静态度中心性，**不更新**——所以会选出一堆覆盖同一批危险对的冗余字段 |
| **单泄露基线** | 按 `max_c v_c({f})` 排序取前 k | 传统单字段敏感度方法（IGNN 口径） |
| **随机** | 随机删 k 个（20 次平均） | 下界对照 |

**评价标准有两层**：
- (a) **覆盖率** `f(P)/W`——低阶真值口径，图 1a；
- (b) **真实最坏泄露** `max_c v̂_c(一般字段 ∖ P)`——用 oracle 查补集，这是 Part B。

补充实验（MLP-oracle + 独立 test 重训）在 k=24 的结果：

| 策略 | MLP-oracle 均值±σ | 独立 test 重训 |
|---|---:|---:|
| 低阶协同贪心 | **0.734 ± 0.004** | **0.783** |
| 加权度 | 0.861 ± 0.002 | ~0.963 |
| 单字段泄露 | 0.861 ± 0.005 | ~0.963 |
| 随机 | 0.980 ± 0.002 | 0.983 |

---

**72 号 Part A 比的是「用什么信号做贪心」的两条搜索路线**（层次不同！）：

| 路线 | 怎么做 |
|---|---|
| **direct（纯 oracle 贪心）** | 从 k=0 开始，每步遍历剩余字段，用 oracle 实测 `max_c R²(共享 ∖ {f})`，选下降最多的那个。内循环 K=50 选字段，选定后 K=200 复核记录 |
| **hybrid（混合）** | **前 24 步用低阶贪心**（不查 oracle，纯低阶真值，便宜且稳，跑到 k\*=24）；**从第 25 步起换成 oracle 贪心**继续 |

所以"两种方式"的区别是**信号来源**：低阶真值 vs oracle 实测。
hybrid 就是"前 24 步用低阶、后面用 oracle"。

**评价标准**：独立 test 上的重训真值最坏泄露（以补充实验为准）：

| k | 低阶/混合 + MLP | 纯 MLP-oracle | 原 GNN 混合 | 原 GNN 直接 |
|---:|---:|---:|---:|---:|
| 24 | 0.783 | **0.777** | — | 0.844 |
| 27 | 0.652 | **0.603** | 0.648 | 0.814 |
| 30 | **0.457** ✅ | 0.578 | — | 0.813 |

⚠️ 注意第 4.1 节：72 号原始的 "Goodhart" 结论已被补充实验推翻。

#### Q8.2 三阶以上没考虑 —— 这是最明显的洞，而且修起来很便宜

现在 `f(P)` 只覆盖危险单字段 + 危险字段对。**没有任何三阶及以上的项。**
但 68 号已经认证了 **314 条强三阶协同**、最强 syn3 = 0.455
（燃气MW + 燃气占比 + 负荷预测 → 净交换功率）。
防护集完全可能把某个三元组的三个字段全留下。

> **修法：从「图上的顶点覆盖」推广到「超图上的击中集（hitting set）」。**
>
> ```
> D = { 危险项 T : |T| ≤ 3（或任意阶）, max_c v_c(T) > τ }
> f(P) = Σ_{T ∈ D : T ∩ P ≠ ∅} w_T
> ```
>
> **好消息：命题 1 的证明原封不动成立。**
> `f(P) = w(∪_{i∈P} S_i)`，其中 `S_i = {T ∈ D : i ∈ T}`，
> 仍然是**加权覆盖函数**，对**任意阶**都单调次模，
> 所以 (1−1/e) 保证完全保留。
>
> **代码改动：`coverage()` 里加一个三元组循环，大概 5 行。**

**更进一步**：如果做了 Q6 的 **H3 剥离法**，得到的极小充分集 `{M}`
就是超边集合，防护集 = 击中所有 M 的最小集合。
**这时"防护集"和"高阶协同发现"就是同一个数学对象的两面**
——故事完整度会上一个台阶。

#### Q8.3 低估问题怎么改进

用户说"随便说的"，但方向对。四个层次，按推荐排序：

1. **共形上界 + 悲观贪心（最推荐）**。见 Q3 的 C1。
   让贪心去最小化 `v̂_up` 而不是 `v̂`。数学上这是"最小化真值的一个上界"，
   **保证不会假达标**，而且天然免疫 Goodhart
   ——你不可能通过过拟合把一个有覆盖保证的上界压下去。
   **这一条同时解决：72 号原始结论、补充实验的 k=29 假达标、
   以及"oracle 达标 ≠ 真达标"三个问题。**
2. **对抗性掩码重训 oracle**（Q2 的 D2）。gap 大是因为防护后的补集是分布外的；
   把这些补集加进训练掩码分布，闭环迭代 2–3 轮。**这是治本。**
3. **重训 in-the-loop，但只在最后几步**。前 k−3 步用 oracle（便宜），
   最后 3 步每个候选花一次重训（每次 6–7 min × 剩余字段数 ≈ 2 小时）。
   用预算换确定性。
4. **信任域 / 保守步长**：oracle 贪心每步不选"下降最多"的那个，
   而选"下降 ≥ 阈值**且**低阶覆盖收益也最大"的那个
   ——两个信号必须同时同意才动。这是廉价的正则化，能压住单一代理的误差。

#### Q8.4 另外两个我认为必须指出的问题

**(a) (1−1/e) 证书的适用范围被夸大了**

覆盖函数 `f(P)` 单调次模 ✓（命题 1 证明正确）。
**但真正的目标 `max_c v_c(补集)` 不是次模的**——它是 max 的复合，
甚至不满足可分解性。

所以 **(1−1/e) 只对代理目标（覆盖率）成立，对真实的最坏泄露不成立**。
71 号"k≤4 贪心/最优比值 = 1.0000"也是在**覆盖率**上算的。

> **必须在论文里写清楚**，否则是硬伤（审稿人一眼能看出）。
>
> 可行的补强：报"**真实最坏泄露**"口径下的小预算暴力最优对比。
> k ≤ 3 时 C(44,3) = 13244 次 oracle 查询，用 K=0 的话几分钟就能跑完。
> 如果贪心在真实目标上也接近最优，那是更强的结论；
> 如果不接近，那也是个诚实且有信息量的发现。

**(b) 删字段这条路本身的天花板**

补充实验的最终数字：**要压到 τ=0.5 得删 30/44（68%）字段**。
这说明"删除式脱敏"在强攻击者假设下代价巨大。
72 号已经把它写成"给数据方的核心警示"——这是对的，
但更好的做法是**顺势把它变成下一个正面结果**：

> **把防护机制从"删除"推广到"加噪 / 聚合 / 粗化"**，
> 用同一套 oracle + 贪心框架，在"效用损失"预算下最小化最坏泄露。
>
> 这时得到的是一条**隐私–效用前沿曲线**，而不是一个"必须删 68%"的坏消息。
>
> **技术上几乎不用改**：把 mask 从 {0,1} 放宽到 [0,1]（表示"加噪后的信噪比"
> 或"粗化程度"），oracle 训练时就用连续 mask——现有架构里
> `x⊙m` 的 `m` 本来就是浮点。
>
> 而且加噪机制天然能接差分隐私的语言（虽然威胁模型不是 DP），
> 审稿友好度大幅提升。

#### Q9.2 论文层面：方法新颖性的定位

65/66 号的结论是"不再押模型技巧，转向问题形式化 + 测量方法学"。
**我部分同意但不完全同意**——测量方法学单独撑一篇偏薄，
而且"我们试了四个方法都失败了"很难作为主线卖点。

**我建议的组合**：

```
问题形式化      v_c(S) 集合函数 + sup 语义 + 逐 conf（56/60/63 已有）
      ＋
有保证的测量协议  共形上界：便宜筛选 / oracle 精修 / 重训认证三层，
                每层有覆盖保证而非经验校准          ← 新（Q3）
      ＋
有保证的搜索     共形 UCB 剪枝 + 逐次减半 + 剥离法极小充分集，
                替代启发式 Apriori                 ← 新（Q6）
      ＋
应用            超图击中集防护集 + 隐私-效用前沿    ← 扩展（Q8）
```

这四块里，**共形保证**和**剥离法**是真正新的、可辩护的技术贡献。
而且它们和已有的四个负结果**不冲突、反而互补**——
那些负结果正好论证了"**既然没有更聪明的模型，就必须有更聪明的协议**"。
这是一个连贯的、有说服力的叙事，比"我们试了很多模型都不行"强得多。

#### Q9.3 几个较小但值得做的点

- **补齐 GCN 的审计样本量**。69 号的字段对/三元组 GCN 对比各只有 9 个样本，
  自己也注明"不应外推"。如果要对外声称任何 GCN 相关的结论，
  这个样本量必须扩（每个 30+ 起）。
- **`total_gen` 与 `metered_load_mw` 高度同构**（核查 A 里 top10 有 5 对是同一字段对
  打两个 conf）。这意味着 12 个 conf 的**有效自由度**远小于 12。
  建议做一次 conf 之间的相关性/聚类分析，在论文里说明
  "12 个 conf 实际是 K 个独立的泄露目标"，避免被质疑"重复计数"。
- **`congestion_price_da/rt` 的天花板只有 0.65**（核查 D），
  意味着它们对任何防护策略都不敏感（本来就推不准）。
  报"最坏 conf 泄露"时，这两个几乎永远不是瓶颈——
  值得在论文里说明"最坏泄露实际由哪几个 conf 主导"。
